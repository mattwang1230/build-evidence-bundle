# 证明对象与证据链硬门槛

本 reference 只规定证据清单的组织与边界，不把任何具体案件事实预先写入模板。生成正式卷前，证明对象、证据内容和法律意义必须分开；无法由材料回指的内容只能进入待核对草稿。

## 一、硬门槛

每个证据组至少有一个可识别的 `group_id`、一项 `proof_object`、一个或多个 `materials`，并至少被一条 claim 覆盖。每个材料必须有全局唯一的 `material_id`。v19 先以 `proof_targets[]` 列出经书状或用户说明确认的请求、抗辩、反驳或背景目标及其法律要件，再把证明对象拆成 `proof_claims[]`。每项至少包含：

- `claim_id`、`text`；
- `type`：`fact` 或 `legal_significance`；
- `fact_level`：`element_fact`、`indirect_fact`、`auxiliary_fact` 或 `procedural_fact`；
- `role`：`direct`、`indirect`、`corroborative`、`rebuttal` 或 `linking`；
- `purpose`：为什么提交该材料，拟支持/反驳哪项诉讼请求、仲裁请求、抗辩或证明要件；
- `purpose_basis`：保留 `{kind, reference, status}`，并增加 `{target_kind, target_id, legal_element}` 精确回指 `proof_targets[]`；用途来源仍区分起诉状/答辩状/仲裁请求（`pleading`）、用户明确说明（`user_statement`）和仅由材料归纳（`materials_only`），以及 `confirmed`/`provisional` 状态；
- `material_refs[]`：每个引用包含 `material_id`、页码 `page` 和区域 `region`；
- `boundary`：写明材料不能证明什么、还需要什么补强；只保存在 Manifest/QA 和 AI 交付回复，不直接进入 Word 证明对象栏。

一条 claim 不得脱离材料回指，也不得只复述材料内容而不说明提交用途；旧 v1/旧 v2 缺少 `proof_targets`、`fact_level` 或目标/要件映射时只能生成草稿。一个证据组没有 claim、一个材料没有被有用途的 claim 回指、一个已列法律要件没有任何证据覆盖，均阻断正式版。同一款项、主体或日期存在冲突时，不得由程序选择一方。正式版必须同时通过主体、日期、金额、付款状态、证明范围和原始载体核验；任一核验为 `unresolved`、存在 `unresolved_issues`、材料损坏/不可读、缺少原始载体、claim 无回指或存在冲突，均不得生成正式版。

视频截帧 claim 还必须同时回指截帧 `material_id`、原视频 `source_id`、数值时间和格式化时间码；时间码只定位画面，不能单独证明视频未剪辑、账号身份、时间真实性或完整上下文。`public_demo_copy`、`social_media_copy` 或 `unverified_local_video` 可以用于功能演示和待核草稿，但不得作为案件原始载体放行正式版。

用途依据是独立硬门槛：`pleading/confirmed` 可以在其他门槛全部通过时进入正式版；`user_statement/confirmed` 还必须留下可复核的具体用户说明；任何 `provisional`、任何 `materials_only`、`materials_only/confirmed` 或“用户已确认”等泛化留痕都只能生成草稿。用户拒绝补充信息后可以继续整理，但不得删除 `validation.unresolved_issues[]`、不得把对应核验项改为 `resolved`，也不得用模型推断补齐。

用途审查还要防止“实质同义复述”：仅把 `text` 改写成“用于支持本案请求的事实：该页面记载……”不构成新的证明用途。去除模板词后的核心内容与原子事实高度重合时，必须补充具体请求内容、抗辩理由或证明要件；若已有具体返还、赔偿、履行、合同条款或书状段落等锚点，则不因事实短语重合而机械阻断。

Word 的 `proof_object` 也不得只是“证明合同内容”“证明聊天记录”“证明转账记录”等材料摘要。推荐写成积极事实命题并用短句标明其对应的具体请求、抗辩或法律要件；不强制以统一模板开头。间接事实必须保持为间接事实，不能因其服务某项法律要件就改写成材料已经直接证明该要件成立。

“对应本案诉讼请求”“对应法律要件”“对应第1项请求”等只有类别或序号、没有请求内容或要件内容的句子仍属空泛用途，不能进入正式版。书状用途依据须回指具体页码、段落、条项或明确章节。跨组衔接须逐一写明实际组号或 `group_id`；“结合证据”不能替代具体组间关系。

跨组共同证明必须使用 `cross_group=true` 与 `role=linking`，并在 `purpose` 中说明组间衔接。内部覆盖矩阵按目标与法律要件列出 `covered`、`partial`、`uncovered`、`conflict`；`partial` 只作人工充分性复核提示，机器不得仅因证据是间接证据就自动否定证明力，但 `uncovered`、无用途材料和未解决冲突不得进入正式版。

以下情形为一票否决或至少转入草稿人工复核：

1. 以图片、昵称、头像或单一账户名称自动确认身份、签章真实性或责任主体；
2. 把当事人陈述、证据清单的证明目的、二手摘要写成法院已经查明的事实；
3. 以单笔回单替代全部付款链，或把合同约定金额自动写成实际支付、已清偿或损失；
4. 在没有完整上下文、原件或裁判原文时写“胜诉”“承担责任”“当然连带责任”“材料直接证明承认”等结论性措辞；
5. 以视觉相似或文件名相近自动删除材料。只有 SHA-256 完全相同的内容可建立 canonical/alias 关系，视觉相似但哈希不同仍须人工核验。
6. 把社交媒体下载/导出副本、宣传视频或未核实本地视频写成案件原始录屏，或据其平台时间码反推原始证据真实性。

上述高风险措辞扫描同时覆盖 `text`、`boundary`、`purpose` 和 `purpose_basis.reference`；机器提示不能替代人工确认身份、真实性或法律责任。

## 二、推荐证明链

按请求权基础或用户确认的清单排序；组内通常按“主体与关系—行为发生—履行/付款—催告或承认—结算/签字原件”组织。每一项事实都应有明确落点：

| 层次 | 可写内容 | 不可越界 |
| --- | --- | --- |
| 直接事实 | “M001 第1页/签署栏载明日期为……” | 不写成签署人身份、合同履行已完成 |
| 间接/印证事实 | “M002 与 M003 相互印证……，仍需……” | 不把推断写成原件记载 |
| 提交用途 | “用于支持起诉状中的付款请求；用途依据为起诉状第3页” | 不把材料内容、当事人主张直接写成法院已认定事实 |
| 法律意义 | “结合……拟证明……；适用条件仍待核对” | 不预判裁判结果或责任承担 |
| 证据边界（内部） | “本图不能证明付款归属/主体关系/真实性” | 不写入 Word 证明对象栏，也不用“无法证明”掩盖已存在的冲突 |

清单表中的证明对象宜精简，但应至少写出该组拟证明的事实及其服务的请求/抗辩；表格不写“仍待核”“不能单独证明”“仍需补强”或原件、真实性、送达、付款/清偿状态等待核尾句。每一项 claim 的原子事实、`purpose`、用途依据、材料回指和 boundary 在 Manifest/独立核验侧车文件中逐条保留，详细缺口由 AI 交付回复说明。证据表第三列使用整卷物理“页码”，由附件书签和 `PAGEREF` 域显示“第X页”或“第X-Y页”；页脚使用 `PAGE` 域连续编号。律师可用 Word 的附件页只保留证据编号、证据名称和组内页次；路径、哈希、内部编号、`canonical` 和原始载体定位继续留在 Manifest/QA 侧车文件，保证他人可以反向复核而不挤占主卷。纯负面边界不得作为完整 `proof_object`；清理后没有积极命题时必须停止生成。“尚未付款”等经材料和核验支持的实体事实不属于防御性边界。

## 四、正反例

### 可接受

Word 证明对象示例：

```text
协议签署页载明日期为2024年5月11日；对应起诉状第1项价款请求中的协议形成时间事实。
```

相应的内部 claim：

```json
{
  "claim_id": "C001",
  "text": "M001 第1页/签署栏载明协议日期为2024-05-11，拟证明文书记载的签订日期。",
  "type": "fact",
  "fact_level": "element_fact",
  "role": "direct",
  "purpose": "用于支持起诉状中关于协议形成时间及相应请求权要件的主张。",
  "purpose_basis": {
    "kind": "pleading",
    "reference": "起诉状第2页第3段",
    "status": "confirmed",
    "target_kind": "claim",
    "target_id": "REQ-01",
    "legal_element": "协议形成时间"
  },
  "material_refs": [{"material_id": "M001", "page": 1, "region": "签署栏"}],
  "boundary": "不能单独证明签字人身份、签章真实性或协议已履行。"
}
```

### 不可接受

```text
“材料直接证明被告承认债务并应当承担责任，原告必然胜诉。”
```

该表述同时跳过了主体锁定、完整上下文、承认法律效果和裁判结论；应拆成可回指的事实 claim，并在 boundary 中保留待核事项。
