# 证据材料筛选、填充与质检规则

## 一、原件优先，截图用于阅卷

Word 内嵌图片是阅卷副本，不替代原始证据。始终保留原手机、原应用聊天、录屏、转账账单、纸质原件和未经压缩的图片。

Manifest v2 的每个材料都必须写明对象形式且可定位的 `original_carrier` 或 `carrier`。对象使用 `carrier_location`、`path`、`location` 或 `region`；定位值不能是“已核对”“已留存”“见原件”等确认语，也不能只写“纸质文件”“微信聊天记录”“原件”等载体类型词。普通证据引用中的 `page`＋`region`（如“全图”“聊天区”）不能替代原始载体位置。

## 二、录屏截帧

需要从录屏截帧时，先使用 `scripts/extract_video_frames.py` 真实解码本地视频。默认策略为“场景变化＋最大间隔”，也可由用户明确给出时间码；策略和参数必须写入 `video-frame-index.json`，不得随机抽样。Skill 不自动下载媒体工具，不读取远程 URL，也不提供动态打码、OCR脱敏、静音或视频元数据清理。

自动截帧至少覆盖：

1. 联系人或群资料页；
2. 关键聊天前后各一段上下文；
3. 金额、日期、收付款主体同时可见的画面；
4. 催告、承认、结算或签字；
5. 能显示连续滚动过程的原录屏文件。

截帧文件名使用：

`组号-序号-录屏名-时间戳-待证事实.png`

工具输出文件名可先使用稳定帧号和时间码；归入证据组后再按上述业务格式命名。必须同时保留结构化索引：

`录屏文件名｜起止时间｜截帧文件｜关键内容｜对应清单编号`

每帧至少记录 `frame_id`、数值秒、格式化时间码、原视频 SHA-256、输出帧 SHA-256、视频流编号、方向归一状态、`source_kind` 和结构化 `original_carrier.path`。按数值时间排序，不按文件名或字符串时间排序；完全相同输出帧只保留一个 canonical，但所有重复时间码继续保存在 alias 索引中。视觉相似但内容不同的帧不得自动删除。

不得只保留截帧后删除录屏。`source_kind` 默认是 `unverified_local_video`；只有用户明确核验原录屏时才可写 `original_recording`。`public_demo_copy`、`social_media_copy` 及未核实本地视频可以截帧和制作演示草稿，但不能作为案件原始载体进入正式举证版。

## 三、金额四口径

所有款项分别记录：

- 订单额；
- 二维码/申请额；
- 实际支付额；
- 对方认可或结算额。

另列：

- 已清偿金额；
- 未清偿金额；
- 计算公式；
- 证据来源。

任一口径不一致，正式版生成前必须由用户确认。表载合计与分项合计不一致时，同时展示两者和差额，不得擅自挑选。

## 四、日期核对

日期优先级：

1. 原始电子数据完整时间；
2. 转账回单/账单详情；
3. 书证记载日期；
4. 截图界面日期；
5. 文件创建/修改时间；
6. 文件名和当事人口述。

低优先级来源不得覆盖高优先级来源。聊天只显示“周一”“3月5日”时，需从上下文或原始数据补足年份。

## 五、图片选择与去重

- 完全相同哈希只保留一份；
- 同一聊天内容的不同裁切版，优先保留主体、时间和上下文更完整者；
- 同一事实存在“聊天截图＋账单详情”，两者均保留，因为证明功能不同；
- 模糊图片不得为节省页数而放大到失真；
- 对含身份证号、手机号、银行卡号的材料，如需公开展示，由独立发布流程制作脱敏副本并另行复核；本 Skill 只保留证据编排和载体边界，原件另行保存。

## 五之一、显示旋转

- EXIF 方向由程序先规范化；不得根据长宽、文件名或肉眼结果自动猜测人工旋转。
- 如仍需修正，材料字段 `display_rotation_degrees_clockwise` 必须由人工明确填写，只接受 `0`、`90`、`180`、`270`，缺省为 `0`；无效值阻断正式版。
- 预检、附件页头和来源索引均记录实际采用的顺时针旋转值。旋转只改变展示方向，不裁切原图。

## 六、分页和缩放

- 清单表格结束后插入分页符；
- 每张材料独立成页、独立成段；
- 等比例缩放到版心内，绝不裁切；附件页头与主图按页内可用高度共同计算，长来源、原始载体或 fact 不得把主图挤到下一页形成 header-only 空白页；
- 纵向长截图优先受页面高度限制；
- 横向执照、表格优先受页面宽度限制；
- 图片居中，段前段后为 0；
- 每个附件页页脚显示整卷连续物理页码；证据表第三列“页码”用书签与 `PAGEREF` 域回指该组首末附件页，显示为“第X页”或“第X-Y页”，不得用材料数量冒充页码。
- 附件页头与主图必须保持在同一页；长来源、原始载体或 fact 文本应先缩小图片可用高度，避免页头溢出后形成空白页。

若一张图片缩放后文字不可辨，应拆分为“全貌页＋局部放大页”，两页均注明来自同一原件，并分别进入该组页码范围。

## 六之一、Office 派生页

- XLSX/PPTX/DOCX 原文件先只读预检，不能直接作为图片附件；
- 转换只写入全新隔离目录，不使用用户 Office profile，不重算公式或展开隐藏内容；
- 每页必须由 sidecar 回指 source_id、Office 内部位置、PDF 页和 PNG 摘要；
- 工作表/范围或幻灯片纳入范围须由用户确认；
- 字体替换、空白页、仅页头、裁切、不可读及隐私复核任一未完成时不得入卷；
- Office gate 非 PASS 时，即使案件整体允许草稿，也不得生成含该派生页的 DOCX。

## 七、填充前检查

- [ ] 清单顺序已由用户确认或有明确请求权结构；
- [ ] 每张图片已归入唯一主组；
- [ ] 主体身份有资料页或其他补强；
- [ ] 关键聊天含上下文；
- [ ] 转账显示时间、金额、对方和状态；
- [ ] 结算单有全貌及签字细节；
- [ ] 金额、日期、已清偿状态无冲突；
- [ ] 证明对象未超出材料内容；
- [ ] 原始载体仍在。
- [ ] 视频截帧有数值时间码、结构化索引，且原视频摘要在截帧前后未变化。
- [ ] 未核实或公开/社交媒体派生视频未被当作案件原始载体。

## 八、填充后检查

- [ ] 表格行数＝证据组数＋表头；
- [ ] 图片数＝各组材料数之和；
- [ ] 表头为“页码”，页脚含 `PAGE` 域，各组页码单元格含可解析的 `PAGEREF` 域；
- [ ] Word 更新域或渲染PDF后，各组“第X页/第X-Y页”与实际附件页一致；
- [ ] 表格第N项后首先出现该组第1张图；
- [ ] 组间无串页、漏页、重复页；
- [ ] 第一张、最后一张和每个组边界已抽查；
- [ ] 视频帧按数值时间码排序，重复时间码和完全相同帧的 alias 仍可追溯；
- [ ] DOCX 可打开并可编辑；
- [ ] 来源索引以固定字段表格保存，表头可重复，长文本不使用竖线串联字段；
- [ ] 有条件时完成页面渲染检查，至少抽查长页头、长图、来源索引、附件顺序和空白页。
- [ ] 已生成内部覆盖矩阵；不存在“材料未被任何有用途的 claim 回指”或“已列法律要件没有证据覆盖”。
- [ ] 仅有间接/辅助覆盖的要件已由律师人工复核，机器未把间接事实改写成直接要件事实。
- [ ] 跨组共同证明使用 `cross_group=true`、`role=linking`，且 purpose 明确写出组间衔接。
